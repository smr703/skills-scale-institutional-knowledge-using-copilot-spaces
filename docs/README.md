# OctoAcme Docs

This directory contains OctoAcme project management process documents and a brief overview of how teams move work from idea to delivery.

OctoAcme uses a lightweight but structured lifecycle that starts with initiation, moves through planning and execution, and ends with release and retrospective improvement. Teams begin with a clear business need, aligned stakeholders, success metrics, a one-pager, and an approved path into planning. Planning then turns that work into a prioritized backlog with acceptance criteria, estimates, milestones, dependencies, and a documented Definition of Done.

Delivery depends on clear roles and shared ownership. Project Managers coordinate schedules, risks, dependencies, and communications. Product Managers define outcomes, prioritize the backlog, and measure success. Developers implement features, help estimate work, maintain tests and documentation, and surface technical risks, while QA and stakeholders validate acceptance criteria and progress at key milestones.

Execution stays visible through a shared project board and regular communication rhythms such as standups, delivery syncs, sprint demos, and stakeholder updates. Quality is built into the process through small pull requests, linked issues and acceptance criteria, automated testing and security checks in CI, manual QA when needed, release readiness checks, and retrospectives that feed improvements back into the backlog.
